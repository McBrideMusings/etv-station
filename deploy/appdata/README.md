# `deploy/appdata/` — the host's config folder, mirrored

This directory is a local copy of the folder the deployed container runs out of
(`/config` inside the container, an appdata path on the host). Editing a channel
here and pushing the folder is a config change; rebuilding the image is a code
change. They are separate on purpose — a new channel or a tweaked block should
not require a rebuild.

```
deploy/appdata/
  station.yaml                        the station config the daemon loads —
                                      carries the ffmpeg + normalization block
                                      every channel body is built from
  channels/
    020-trending/                     one directory per channel
      channel.yaml                    the channel config
      overlay.toml                    its overlay spec (`config: "overlay.toml"`)
      logo.png                        the mark overlay.toml's `path` points at
                                      (just "logo.png" — same directory)
    ...
  shared/                             overlay specs + assets more than one
                                      channel points at (e.g. the Pierce and
                                      Madison marks), referenced from a
                                      channel dir as `../../shared/x.toml`
  plugins/                            scorer scripts a channel's pool names via
                                      `plugin:`, resolved relative to the
                                      channel file (so `../../plugins/x.rhai`)
```

Every path a channel or overlay file names — `overlay.config`, an overlay
layer's `path`, a pool's `plugin`, a `block =` reference — resolves relative
to the file that names it, not to any fixed directory. That is what makes the
per-channel layout possible: a channel's own overlay and logo sit right next
to it, and only the handful of marks two channels share had to move to
`shared/`. Adding a channel is one new `channels/<name>/` directory plus
`admin deploy files` — `station.yaml`'s `channels:` glob (`channels/*/channel.yaml`)
picks it up with no edit there.

A channel's lineup/guide display name is its own `display_name:` in
`channels/*/channel.yaml` (#158) — there is no `presentation.json` anymore;
it is never read, even if one is still sitting on a host from before this
change.

Everything else under `/config/etv-next` on the host — `lineup.json` and
`channel{N}.json` — is generated by the container at every start from
`station.yaml`, so it is never edited here and never pushed.

What the container supplies, so these files stay host-agnostic:

| Environment variable | Value in the image | Effect |
|---|---|---|
| `ETV_STATION_OUTPUT_BASE` | `/data/playout` | overrides `output_base`, so playout JSON lands on the data volume |
| `ETV_STATION_CATALOG` | `/data/catalog.db` | overrides `catalog_path` — a rebuildable cache, not config |
| `ETV_HLS_OUTPUT` | `/data/hls` | ETV-next's HLS working set |
| `ETV_PORT` | `8409` | the port the lineup, `channels.m3u`, and `xmltv.xml` are served on |
| `PLEXDB_SNAPSHOT_PATH` | `/data/plexdb.snapshot.db` | the taste-ranking snapshot a pool's `datastores` grant expands `${PLEXDB_SNAPSHOT_PATH}` to (#256) — the same `/data` mount `ETV_STATION_CATALOG` uses, written by the separate plex-db-ex container (plex-db-ex#43) with no copy step in between |

Under `ETV_STATION_OUTPUT_BASE` the daemon also keeps `history.db` — the
play-history ledger, one sqlite database shared by every channel (#111).
Unlike `catalog.db` it is **not** a rebuildable cache: it is the only record
of what each channel has aired, migrated once from each channel's old
`.history` file and appended to ever since. Back it up with the rest of the
data volume; deleting it loses every channel's resume position.

Media roots — `ETV_STATION_SOURCE_ROOTS` (directories the daemon scans into
the catalog) and `ETV_STATION_IDENTITY_ROOTS` (the root stripped when deriving
a local item's identity, a separate decision — #243) — Plex credentials
(`PLEX_URL`, `PLEX_TOKEN`), and Tautulli credentials (`TAUTULLI_URL`,
`TAUTULLI_API_KEY`) are per-host, so they come from the container's
environment rather than from any file here. Tautulli is what a scorer plugin
ranks by: without it the watch history the daemon hands the script is empty,
and the ranking is arbitrary.

Only `README.md` is committed — the channels, blocks, overlays, and the
station config itself (including its `ffmpeg:`/`normalization:` block) are
personal, the same way `examples/channels/` is.
