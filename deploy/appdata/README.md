# `deploy/appdata/` — the host's config folder, mirrored

This directory is a local copy of the folder the deployed container runs out of
(`/config` inside the container, an appdata path on the host). Editing a channel
here and pushing the folder is a config change; rebuilding the image is a code
change. They are separate on purpose — a new channel or a tweaked block should
not require a rebuild.

```
deploy/appdata/
  station.yaml                        the station config the daemon loads
  channels/                           one file per channel
  blocks/                             block definitions the channels reference
  overlays/                           overlay specs + their scripts
  plugins/                            scorer scripts a channel's pool names via
                                      `plugin:`, resolved relative to the
                                      channel file (so `../plugins/x.rhai`)
  etv-next/
    normalization.default.json        the ffmpeg + normalization block every
                                      channel body is built from
    presentation.json                 optional display names / per-channel
                                      playback overrides
```

Everything else under `/config/etv-next` on the host — `lineup.json` and
`channel{N}.json` — is generated by the container at every start from
`station.yaml`, so it is never edited here and never pushed.

What the container supplies, so these files stay host-agnostic:

| Environment variable | Value in the image | Effect |
|---|---|---|
| `ETV_STATION_OUTPUT_BASE` | `/data/playout` | overrides `output_base`, so playout JSON lands on the data volume |
| `ETV_STATION_CATALOG` | `/data/catalog.db` | overrides `catalog_path` — a rebuildable cache, not config |
| `ETV_HLS_OUTPUT` | `/data/hls` | ETV-next's HLS working set |
| `ETV_PORT` | `8409` | the port the lineup, `channels.m3u`, and `xmltv.xml` are served on |

Media roots (`ETV_STATION_SOURCE_ROOTS`), Plex credentials (`PLEX_URL`,
`PLEX_TOKEN`), and Tautulli credentials (`TAUTULLI_URL`, `TAUTULLI_API_KEY`)
are per-host, so they come from the container's environment rather than from
any file here. Tautulli is what a scorer plugin ranks by: without it the watch
history the daemon hands the script is empty, and the ranking is arbitrary.

Only `README.md` and `etv-next/normalization.default.json` are committed — the
channels, blocks, overlays, and the station config itself are personal, the same
way `examples/channels/` is.
