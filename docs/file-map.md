# File map

Concise repo navigation. See [PRD §Architecture → Repository layout](/PRD#repository-layout) for the rationale.

## Top-level

| Path | What |
|---|---|
| `Cargo.toml` | Workspace manifest. Members: `crates/etv-station`, `crates/etv-query-test`, `crates/etv-overlay`, `vendor/plexdb-reader`. Excludes `vendor/etv-next`. |
| `Cargo.lock` | Workspace lockfile. |
| `package.json` | VitePress devDep + `docs:dev` / `docs:build` scripts. Docs-only; no runtime JS. |
| `bun.lock` | Bun lockfile for the docs `package.json`. |
| `rustfmt.toml` | Workspace formatting config. |
| `CLAUDE.md` | Repo-level agent guidance: build/run, the vendored-ETV-next and vendored-plexdb-reader rules, docs convention. |
| `Dockerfile` | Multi-stage build of the whole stack: one Rust builder compiles release `etv-station` + `etv-overlay`, a second compiles the vendored tree's `ersatztv` + `ersatztv-channel`, and the runtime stage (ErsatzTV's own ffmpeg image) carries all four plus a software-Vulkan stack for headless overlay rendering and `iproute2` for `ss` — asking whether a frozen player still holds a connection open is a question only the server's own network namespace can answer, and without it the shell answers "command not found" on stderr and exits 0, which reads as "no connections". Same reasoning carries `tcpdump`, `python3`, and the two stream diagnostics, which the runtime stage copies to `/usr/local/bin` and `ETV_DIAG_CAPTURE` switches on. `tcpdump` is given `cap_net_raw+eip` so uid 1000 can capture: NET_RAW is already in docker's default capability set, so nothing has to be added to the run config, and the capture stays non-promiscuous (`-p`) because going promiscuous would need NET_ADMIN, which is not. `curl` and `libxml2-utils` (`xmllint`) are also installed, and `tools/probe-checks.sh` + `tools/soak-probe.sh` are copied to `/usr/local/bin` for the always-on soak-test probe loop (#297). |
| `docker/entrypoint.sh` | Container PID 1 (under tini). Renders ETV-next's config from the station config, creates every channel's playout folder, optionally starts the two packet-level diagnostics, starts the daemon and `ersatztv` — each teeing its stdout to `$ETV_DIAG_DIR/station-etv.log` whenever that dir is writable — then starts the always-on soak-probe loop (#297, `tools/soak-probe.sh` on a `sleep $SOAK_PROBE_INTERVAL_SECS` cadence). Restarts a crashed daemon in place; exits when ETV-next dies. A diagnostic or the probe loop dying is ignored — the wait loop only ends the container for its two real children (station, ETV-next). `station-etv.log` and `ffmpeg-progress.log` are both size-capped by a shared `rotate_log()` (copy-then-truncate, since a long-lived awk writer holds each path open) on a slow background loop — 32MiB x 2 for the station log, 64MiB x 2 for the progress log (#299). |
| `.dockerignore` | Keeps `target/`, `.git/`, docs build output, and scratch out of the Docker build context. |
| `.env.example` | Template for the deploy-related env vars (`APP_IMAGE`, `UNRAID_HOST`, …). Real `.env` is gitignored. |
| `LICENSE` | Boilerplate. |
| `README.md` | Project intro: tagline, status (what exists vs. planned), clone, build/run commands, docs links. |

| `crates/etv-station/src/determinism.rs` | Determinism check (#168): generate a named channel twice from identical inputs — one read-only catalog handle reused for both passes, one pinned seed (an unset one is drawn once and reused, so an intentionally-unseeded channel — #46 — is not misread as a broken plugin), `GenerationState::empty()` for both passes, and one `ScoreInputs` snapshot (including `now`, read once) — and diff the resulting `entry_id` sequences. Reports identical, or the first position where the two disagree plus both entry ids. Diffs `resolve_channel_with_resume`'s output rather than any one hook's call, so it covers both plugin hooks — `pool_provider` and, since #169 landed, `sequencer` — with no per-hook code here. `window_start` is read once and shared by both passes for the same reason `now` is: a sequencer reads it as `ctx.window.from`, so reading the clock per pass would straddle an hour boundary now and then and report a correct daypart script as non-reproducible; sharing it also means both passes seed the same fixed plugin clock (#357 — `score::PLUGIN_CLOCK`, no longer a vector to force apart). Wired to `--check-determinism <channel>` in `main.rs`; not part of normal generation — never called from `daemon.rs`. |
| `crates/etv-station/src/audit.rs` | The station's own side of the audit-trail contract (ADR 0011), for the producers that are not a Rhai plugin. `push_stage` appends one `{stage, by, verdict, detail}` record onto an item's `metadata.audit` array, creating both on the first stage, so a plugin pool's ranking record and a built-in stage accumulate in the order they acted rather than overwriting each other. `stage` is not validated here — every caller is station code passing a literal from `score::KNOWN_STAGES`, unlike the plugin path where the name arrives from a script and is refused at pick time — so a `debug_assert` catches a typo in tests at no daemon cost. A non-object metadata blob drops the record rather than panicking: a missing audit line costs a line in a text file, and `score` already refuses that shape at pick time anyway. Written from `pattern.rs`'s walk, which emits a `pool` stage for every drawn id (#389 shipped the plugin path only, so the 60 channels with no `plugin:` pool reported every item as unexplained). |
| `crates/etv-station/src/audit_report.rs` | The `--audit <channel> [--next N]` one-shot report (#390, ADR 0011): reads the channel's chunk files, drops chunks whose finish is past, flattens and sorts the survivors by start, takes the first N from now forward, and renders each item's start, title and audit trail to a text file whose path it prints. Renders `verdict` and `detail` generically — no station code names a key inside `detail`, so a script adding one needs no change here. Opens no catalog, no plexdb snapshot and evaluates no plugin: the report describes what will actually air, which is a different question from `taste-debug`'s re-simulation of what a scorer would pick now. An item with no `metadata.audit` is reported as unexplained rather than aborting the run — that is every item written before #389 and every item on a channel with no `plugin:` pool. The renderer is separable from the file reading so it can be tested against a fixture list. |
| `crates/etv-station/src/lib.rs` | Library entry point. Re-exports the modules so integration tests and the binary share one surface. |
| `crates/etv-station/src/config/` | YAML config parsing (Phase C block/channel/entries schema): `station`, `channel`, `rule` (`[[rule.blocks]]` includes), `block` (`[program]`/`duplicates`/`[constraints]`/`[[entries]]`), `constraints` (`no_repeat_within`, `separate_by`/`separate_min_gap`), `entry` (kind-tagged item/query/collection/include), `pool` (#72 `pools` + `pattern`: `group_by`/`bucket_order`/`select`/`rotate`/`advance`/`on_short`/`chance`, a `take` that is a count or the word `all`, and a `from` that cuts the slice at `start`/`end`/`random` (#155), plus #115 per-pool `constraints` with `Pool::constraints` resolving a pool's own table against the block default, `BlockInclude::adjacency_reach` converting a pool-draw gap into channel positions, the opaque `config` bag read through `etv_overlay::config_carrier::deserialize_config` so a non-finite float fails the channel at load naming the key — #130, and #289's own pool-level `guide:` (`Pool::guide`) — the rung between the block and the item in `guide.rs`'s cascade, letting a pattern block's pool (a bumper pool interleaved with a films pool, say) carry its own EPG title without renaming its siblings, validated in `validate_block_pools` alongside the rest of a pool's fields), `source`, `mode`, `order`, `filter`, `overlay` (`OverlayDecl` — `clear` / `{file: <path>}` / `{extend: {layers, script, config}}` / an inline `OverlaySpec`, untagged by shape; `resolve_decl` walks station → channel → block and returns the *chain* to fold rather than one winner — a complete spec or `clear` resets it, an `extend` stacks onto it — and `load_chain` folds that chain, re-rooting each level's paths against its own directory before appending its layers, so a station layer naming `shared/logo.png` and a channel layer naming `logo.png` are both correct and end up in one spec; `resolve_channel` loads and geometry-checks the result at every level for one channel, producing the `ChannelOverlays` held on `LoadedChannel` — #48, ADR 0008), `load`, `validate`. `load` resolves every environment reference — the `ETV_STATION_*` overrides and `${VAR}` in local item paths — through an `EnvLookup` function argument, with `process_env` the only reader of the real environment: `load` keeps its signature and hands the chain `process_env`, while `load_with_env`/`resolve_blocks`/`expand_env` take the lookup, so a test supplies a fixed table instead of exporting variables into the running process (#132). |
| `crates/etv-station/src/resolve.rs` | Resolve pipeline (#71): flattens `[[rule.blocks]]` into an ordered `ResolvedItem` list — resolve entries (inline items direct; `query` entries via `Catalog::resolve_query`, each `entry_id` → item; `collection` entries via name lookup + `Catalog::collection_members`, arriving already in stored `position` order so nothing re-sorts them — #107) → block `filter` (#197: `seasons`/`episode_ids`, each set narrows further — `seasons` needs the catalog, `episode_ids` doesn't; entries-block only, rejected on a pattern/sequencer block at validation) → `duplicates` (collapse before order) → `order` (`manual` keeps authored, else `Catalog::resolve_order`) → `mode`, then one channel-level adjacency pass (`constrain::order_no_repeat`) over the concatenated blocks. Takes `Option<&Catalog>`; with one it builds a canonical-path index so a manual `local` item inherits the catalog `entry_id` for its file (manual∩query collapse). Still rejects `include` entries (#69); `fallback` is implemented (#97). `resolve_channel_with_resume` adds the #72 resume map: a pattern block routes to `pattern::build` instead of the entries path and reports where each pool got to. It also carries the `fill` span — the airtime the caller still needs covered — which bounds one generation whichever shape the channel is: a pattern block with no authored `cycles` stops at the window rather than draining its pools (#140), and a channel with no pattern block is seated at its stored list position, cut at the item that covers `fill`, and reports the position it reached (#118). The cut runs before the adjacency pass, so that pass and the daemon's ledger both see exactly the items about to air; item lengths for it come from `estimated_runtimes` (in/out points → `catalog_duration` → one bulk `Catalog::durations_for` → the mean of what is measured → `scoring.nominal_item_secs`). `resolve_channel` passes `None` and is unbounded, starting every list at the top. A block naming `sequencer:` routes to `sequence::build` instead of either path (#169), and `resolve_channel_with_resume` carries a `window_start` — the instant the generation begins airing — so a daypart script asks what hour the generation starts rather than what hour the daemon is computing in. `resolve_channel_with_resume` also seeds `score::PLUGIN_CLOCK` from `window_start` at the top of the function, before any plugin runs (#357) — a plugin's `timestamp()`/`elapsed()` therefore read a value fixed for this generation, never the real wall clock, and two runs of the same generation see the same clock. |
| `crates/etv-station/src/guide.rs` | The `guide:` config block (#158, #289): `GuideConfig` (the channel → block → pool → item cascade, most specific field wins, via two `GuideConfig::cascade` calls made in `resolve.rs` — block∘channel merged once per block, then a pool's own `guide:` merged into that as the middle rung, per drawn item, in `resolve_pool_block_items`), `GuideFields` (raw catalog attributes a template can address beyond `ProgramMetadata` — studio, edition, genres, cast, directors, writers, countries, summary), the plain `{field}` template engine with an `{a|b}` fallback (`render`), `{field}` categories fan-out for a multi-valued field (`render_categories`), and `validate_template` (an unknown field fails config load, naming the field). Rendered against real schedule/watch-history context in `crate::daemon::render_guide_and_attribution`, since resolve time has neither. |
| `crates/etv-station/src/catalog/` | Unified sqlite-backed catalog (#47) — the durable store query-based channels resolve against, plus the ingesters that populate it (`ingest/`: local-FS + Plex). |
| `crates/etv-station/src/catalog/ingest/mod.rs` | Ingest module root; owns the shared `canonical_index` (canonical-path → `entry_id` over all provenance rows, non-`fs:` id wins) that both ingesters use for path-match inherit. Also owns `reconcile_artwork_cache` (#187) — after every ingest, deletes any cached artwork file on disk that no current entry references, so the cache doesn't grow unboundedly as entries come and go. |
| `crates/etv-station/src/catalog/mod.rs` | `Catalog` handle over a `rusqlite` connection (WAL, `foreign_keys=ON`). Upsert/read API for entries, provenance sources (incl. `all_sources` for ingest path-match), external ids, tags, and collections; two provenance rows on one `entry_id` = a deduped item. An external id is keyed `(namespace, value, kind)`, not `(namespace, value)` — `add_external_id`/`entry_id_for_external_id` both take the media type, because tmdb/tvdb numbers only identify a work within one type (#340). Two bulk lookups exist because the pattern engine asks them of every item of every pool on every generation: `show_ids_for` (series grouping) and `durations_for` (per-item runtime, so a generation knows when it has covered the window — #140). Nothing here ever deletes an entry: `mark_unseen_sources_missing` / `mark_entries_missing_without_live_sources` set `missing_since` instead (ADR 0006), and `upsert_entry`/`add_source` clear it on any pass that writes the row. `resolve_query` — the pool-selection query, and the only read site that filters — `AND`s on `missing_since IS NULL`, so a missing entry stops being schedulable while every other read (by id, by external id, by source, history, attribution) keeps resolving it. |
| `crates/etv-station/src/catalog/ingest/fs.rs` | Local-FS catalog ingester (#92). `ingest_roots` globs media roots + `ffprobe`s durations; `ingest_files` is the pure catalog-writing core with ingest-time path-match inherit (canonical path reuses an existing `entry_id` — Plex or prior scan — else `fs:<fnv1a>`) and `local_fs` provenance keyed by canonical path (idempotent re-scan). Writes no tags at all: the parent-directory `fs_dir` tag is gone (#123), because `add_tag` only ever inserted and an entry kept every folder its files had ever been in — `item.fs_dir` now derives the folder from `entry_sources.playback_path` at query time. A full pass also reconciles deletions (#144): every row it writes gets one identical `last_seen` stamp, rows left holding an older one (file moved, renamed, or deleted) get `missing_since` set, and an entry whose last live provenance row went with them is marked too (ADR 0006 — marked, never deleted, so `entry_id` stays a durable join key). Gated on `prune_absent` — the same contract as `ingest_collections` — which only `ingest_roots` sets, so a partial scan marks nothing. |
| `crates/etv-station/src/catalog/ingest/plex.rs` | Plex catalog ingester (#91, core). `ingest_items` is the pure core: `resolve_existing` picks `entry_id` by precedence — (1) this item's own Plex `ratingKey`, pinned for life once a prior pass has resolved it (#279, ADR 0009, mirrors `plex-db-ex` ADR-0008); (2) the strongest Plex GUID already known to the catalog (`imdb→tmdb→tvdb→plex`), matched within this item's own media type — matching across it merged a film into a TV episode's guide row (#340); (3) path-match inherit onto a prior FS entry; (4) a fresh derivation, `fs:` fallback when GUID-less. Plex is authoritative so it always upserts metadata (incl. promoted `release_date` from `originallyAvailableAt` (#135), `edition`/`studio`/`absolute_episode`/`summary` (#186) columns) + records every external id + a `plex` provenance row (ratingKey) + genre/cast/director/writer/producer/country tags (each namespace cleared and rewritten per entry, so a tag removed upstream doesn't survive a re-ingest). `PlexIngestStats.summary_missing` counts movies/episodes a full pass wrote with no summary, logged by `daemon.rs` rather than assumed (#186). `entry.show_id` is derived from the show's own GUIDs by `derive_entry_id`, not its title, falling back to a hash of the show's Plex `key` (`/library/metadata/{ratingKey}/children`) when it has none — the same rule and the same store `plex-db-ex` derives for the same show, so a rename doesn't orphan a resume cursor and two same-titled shows don't collapse into one series (#274, spot-checked against a live `plex-db-ex` snapshot). `ingest_labels` populates the `label` tag namespace separately (#136): Plex's bulk item listing never carries `Label`, so `PlexClient::fetch_labels` walks each section's label list and fetches each label's section-scoped members directly, and `ingest_labels` reconciles the whole namespace wholesale (`Catalog::clear_tag_namespace`) rather than per entry. `ingest_collections` populates `collections`/`collection_items` (members resolved ratingKey→`entry_id`, in Plex order). Plex attaches genre and external GUIDs to a show, never its episodes, so `fetch_all` also fetches each show's own details once (cached per show, via `PlexClient::show_details`) and copies genres + external ids onto every one of its episode items before `ingest_items` writes the tag rows and derives `show_id` (#196, #274) — the same show-to-episode fan-out `fetch_collections` already uses for membership (#119). `ingest`/`PlexClient` (ureq) is the thin HTTP layer, taking the connection as a `PlexEnv` argument rather than reading the environment itself; `PlexEnv::from_env` is the module's single read of `PLEX_URL`/`PLEX_TOKEN`/`MEDIA_PATH_FROM`/`MEDIA_PATH_TO`, returning `None` for an unconfigured Plex and warning when exactly one of the pair is set (#132). `fetch_accounts`/`PlexAccount` (#281) is a separate, non-ingest read of `/accounts` — every real account this server knows, id `0`'s placeholder excluded by `valid_accounts` — used by `daemon::SharedHistory` to translate a `single_user` channel's Tautulli-space account id into Plex's own id space, since the two disagree for exactly the server's owner (plex-db-ex ADR-0010). A full pass (`since` is `None`) now also reconciles item *deletions*, which it never did before ADR 0006: `ingest_items` reports the one `last_seen` stamp it wrote in `PlexIngestStats.scan_stamp`, and `ingest` hands it to `mark_unseen_sources_missing`/`mark_entries_missing_without_live_sources` so a title pulled from the library stops being schedulable instead of sitting stale forever. Never on a delta pass, where absence means "unchanged". The ingest function takes an `Option<i64>` cursor supplied by `plex_ingest_plan` — `since.is_none()` enables pruning and the missing-marking sweep; a delta skips both since absence means the item is unchanged. `ingest_labels` is deliberately ungated and reconciles the whole namespace on every pass.
| `crates/etv-station/src/catalog/schema.rs` | DDL + up-only migrations (version table, appended-never-edited) for the six locked tables: `entries`, `entry_sources`, `entry_external_ids`, `tags`, `collections`, `collection_items`. Migrations also carry one-off data cleanups where a fact stopped being stored — v4 deletes the `fs_dir` tag rows older binaries wrote (#123), now that the folder is derived from `entry_sources` at query time. v5 adds `entries.summary` (#186) — Plex's `summary` attribute, feeding `ProgramMetadata.description` so the XMLTV guide carries a synopsis. v6 adds `entries.artwork_cache_path` / `entries.artwork_source_key` (#187) — bookkeeping for the cached-artwork file the entry's `artwork_url` points at and the Plex `thumb` path last used to fetch it, written only by the artwork-cache step, never by the ordinary Plex-metadata upsert. v7 adds `entries.missing_since` / `entry_sources.missing_since` (ADR 0006) — the soft delete that replaced the hard one, nullable with no default, so every row an older binary left behind upgrades as live. v8 rebuilds `entry_external_ids` with `kind` in its primary key and repairs what the flat key merged (#340) — TMDB and TVDB number movies and episodes in separate id spaces and Plex reports the bare number, so keyed on `(namespace, value)` alone one integer named two works: 1,479 `(ns, value)` pairs on the live library are shared across kinds (821 tmdb, 658 tvdb, 0 imdb, since IMDb's tt-numbers are one space across every type). `plex-db-ex` keys its own `external_ids` the same way (its issue #23). Because a rating key is pinned to its entry for life (ADR 0009) the 1,446 already-merged entries cannot unwind on their own, so v8 also deletes them (FK cascade takes their sources, external ids, tags and collection rows) and clears `last_plex_ingest`, which sends the next start into a full pass that re-mints each rating key correctly. |
| `crates/etv-station/src/catalog/model.rs` | Typed model: `Entry` plus `Source` / `ExternalNs` / `TagNs` enums for the fixed-set discriminators (open-ended `type` stays a string). |
| `crates/etv-station/src/catalog/identity.rs` | Deterministic `entry_id` derivation: GUID priority `imdb → tmdb → tvdb → plex`, `fs:<fnv1a>` path fallback, and the pure string half of canonical-path (root-strip + separator-normalize). |
| `crates/etv-station/src/catalog/order.rs` | Order resolution engine (#69). `Catalog::resolve_order` applies a `config::Order` to a resolved `entry_id` set: `field:dir` compound sorts via SQL `ORDER BY` (nulls last per term, implicit `entry_id` tiebreaker), `manual` keeps authored order, `random` is a SplitMix64-seeded Fisher–Yates shuffle (deterministic per seed). Every case is a function of the ids alone — a collection's authored sequence is deliberately *not* an order (#107), since `collection_items.position` belongs to the (collection, item) pair and a flat id set can't say which collection to read; it is emitted already-ordered by a `kind = "collection"` entry via `Catalog::collection_members`. `score` went the same way (#108) — it needed a plugin the id list can't reach. Non-sortable fields are errors. |
| `crates/etv-station/src/catalog/query.rs` | CEL→SQL `WHERE` translation (#68). Walks the `cel` AST for a channel `query` expression over `item.*` and compiles it to a parameterised `WHERE` (scalar comparisons/`in`/`contains`/`startsWith`/`matches`, tag/collection/source membership via `EXISTS`, boolean `&&`/`\|\|`/`!`); `Catalog::resolve_query` runs it. `item.fs_dir` is membership too, but derived rather than stored (#123): an `EXISTS` over `entry_sources` comparing the folder computed from `playback_path`, so it names where an entry's files are now and an entry with files in two folders matches either. `register_functions` installs the sqlite functions a clause can call — `REGEXP` (regex crate) and `parent_dir` — on every connection, read-only handles included. Unknown fields and tag comparisons are config errors; empty result is `[]`, not an error. |
| `crates/etv-station/src/catalog/error.rs` | `CatalogError` — open / sqlite / bad-row variants. |
| `crates/etv-station/src/atomic.rs` | `atomic_write_json` — temp file in same dir, fsync, rename. Used by every JSON emission (playout, resume, durations cache). |
| `crates/etv-station/src/constrain.rs` | Post-order adjacency pass (#73). `order_constrained` enforces both spacing rules over one list — the channel's concatenated entries-block items, or (since #115) one pool's own resolved list — plus `conflicts_with_recent`, the same rule asked of a sequence already emitted one item at a time, which is what the pattern draw loop uses: `no_repeat_within` (same `entry_id`) and `separate_by`/`separate_min_gap` (items sharing any value of a multi-valued field), reaching back across the generation seam via the ledger's `tail`. Deterministic greedy (defer a violator, take the first eligible item behind it) plus a bounded swap-repair; unsatisfiable violations are accepted and *reported* via `Ordering::unresolved` so the caller can log them. The list is linear, not circular: `Sequential` plays it once, so its own head and tail never air adjacently. |
| `crates/etv-station/src/history.rs` | `history.db` (#70, #111) — the play-history store: one sqlite row per scheduled airing (`channel`, `entry_id`, `show_id`, scheduled `start`, `played_at`, `error_card`), in its own station-wide database file, deliberately **not** the catalog, because play history is not rebuildable and the catalog's delete-and-re-ingest property depends on everything in it being. The per-series resume cursor is a *projection* of it, so where each show left off lives in exactly one place. Times are stored as epoch nanoseconds rather than RFC3339 text, which sorts wrong when the fractional part is zero. "Last" is the greatest `start`, not the last row inserted, so appending out of schedule order cannot silently rewind a series; equal starts resolve to the later insertion. The resume cursor counts error-card airings and the adjacency tail excludes them. Replaced the per-channel `.history` JSONL, which is migrated once per channel on first start and then left in place. |
| `crates/etv-station/src/backfill.rs` | One-shot repair of `history.db` from the playout files on disk (`etv-station --backfill-history`, `admin backfill-history`). The ledger is written at generation time alongside the chunk JSON, so the two agree by construction — until a coverage heal truncated the ledger from the instant its wipe *started* while regeneration resumed at the surviving frontier, dropping rows for schedule that was still on disk and still aired. That asymmetry is fixed in `daemon.rs`; this repairs the ledgers it already damaged. Reads the chunk files as the record of what was scheduled, which is what they are — rebuilding the index from the thing it indexes, not a second source of truth. Reads **every** invocation in each `data/diag/ffmpeg-argv-ch<N>.log`, unlike `verify-accel.sh`'s newest-block-only scan, because a sliver is rare enough that the last spawn almost never is one. | `tools/attribute-stalls.sh` | Rules on which side stopped first for every `exit status: 75` stall in the container log (#327), so the answer stops being a guess. Cross-checks three signals from the same progress block: the **overrun** from `ffmpeg-argv-ch<N>.log` (an invocation handed `-t X` at `T` should exit at `T+X`, so `kill - (T+X)` is how long ffmpeg outlived its own assignment), the **flatline** from the progress stream (how long `frame=` sat unchanged), and **drops** (whether `drop_frames` was climbing — ffmpeg alive and discarding — or flat — a genuine wedge — or reset — counter went backwards, window spans a respawn — or absent (no data) — across that flatline window). `COUNTER-RESET` is a distinct verdict meaning the window is not attributable; `COMPLETED-BUT-WOULD-NOT-EXIT` and `ENCODER-STOPPED-FIRST` each split on drops into climbing, flat, and no-data variants; `CONSUMER-STOPPED-FIRST` is the fourth. Reads the rotated `ffmpeg-progress.log` first and falls back to the per-session `ffmpeg-progress-ch<N>-*.log` files, so it works either side of `b6f5ac8`. Over ssh by default, or `--local <diag-dir>`; `--at <ISO8601Z> --channel N` attributes one named moment. Read-only. |

| `tools/stream-access-log.py` | Runs inside the container, started by `docker/entrypoint.sh` when `ETV_DIAG_CAPTURE` is set. Parses tcpdump on the served port into one tab-separated row per HTTP message — timestamp, client IP, client port, `>` for a request or `<` for the server's reply, then either `GET /path` + User-Agent or the status code + `len=`/`type=`. Request and reply pair up by client port, so a request with no reply under it is the server going quiet — the shape a freeze takes. Only reply *headers* are kept: the capture filter keeps a returning packet only when its payload starts with `HTTP`, so segment data is dropped in the kernel. | `tools/epg-browser.py` | Textual TUI + JSON CLI for browsing a station's live schedule, reading `/xmltv.xml` + `/channels.m3u` over HTTP (prod, `--local`, or any `--host`) — never the filesystem. Two rows, not three columns (a three-column layout needed 128 terminal columns before titles clipped): the channel list and the programmes sidebar sit side by side on top, with the detail pane spanning the full width beneath them, so the minimum usable terminal is 76 columns. The programmes sidebar shows one row per media item, each row's height snapped to a clock-aligned 15-minute grid, in one of two directions toggled with `h`: forward from the live edge through the end of known EPG data, or history — back up to 7 days, clamped to the oldest retained programme, with now at the bottom so scrolling up travels backwards. History rows carry the calendar date, since a weekday alone can't disambiguate a 7-day window. Every row is prefixed with the channel number and suffixed with the airing item's season/episode, elided title-first so the episode survives a narrow pane; an item's row opens with the block clock if it starts the block, or an indented `›` continuation line at its real unrounded start time if it doesn't, then adds one more line per 15-minute boundary it crosses. A detail pane shows the selected item's full fields under a headline naming show, season/episode and episode title. Auto-refreshes (60 s lineup, 15 s row rebuild) while keeping the selected item's title-and-timestamp-anchored position. `v` opens the channel's live stream in VLC, `a` opens the selected show's artwork. |
| `tools/epg-layout-check.py` | Drives `epg-browser.py`'s TUI under Textual's headless test driver against fixture data — no network, no station — and fails if any pane spills past the terminal edge, if the detail pane is too narrow for the full stream URL, or if the programmes sidebar renders more than one row per fixture programme (block-per-row regression guard for #415). With no arguments it checks both layouts: 80x24 (detail as a bottom row) and 160x45 (detail as a right-hand column). Run by `admin test`, which otherwise only covers the two cargo trees. Takes an optional width and height. |
