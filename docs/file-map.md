# File map

Concise repo navigation. See [PRD §Architecture → Repository layout](/PRD#repository-layout) for the rationale.

## Top-level

| Path | What |
|---|---|
| `Cargo.toml` | Workspace manifest. Members: `crates/etv-station`, `crates/etv-query-test`, `crates/etv-overlay`. Excludes `etv-next/`. |
| `Cargo.lock` | Workspace lockfile. |
| `package.json` | VitePress devDep + `docs:dev` / `docs:build` scripts. Docs-only; no runtime JS. |
| `bun.lock` | Bun lockfile for the docs `package.json`. |
| `rustfmt.toml` | Workspace formatting config. |
| `CLAUDE.md` | Repo-level agent guidance: build/run, submodule rules, docs convention. |
| `Dockerfile` | Multi-stage build of the whole stack: one Rust builder compiles release `etv-station` + `etv-overlay`, a second compiles the submodule's `ersatztv` + `ersatztv-channel`, and the runtime stage (ErsatzTV's own ffmpeg image) carries all four plus a software-Vulkan stack for headless overlay rendering and `iproute2` for `ss` — asking whether a frozen player still holds a connection open is a question only the server's own network namespace can answer, and without it the shell answers "command not found" on stderr and exits 0, which reads as "no connections". Same reasoning carries `tcpdump`, `python3`, and the two stream diagnostics, which the runtime stage copies to `/usr/local/bin` and `ETV_DIAG_CAPTURE` switches on. `tcpdump` is given `cap_net_raw+eip` so uid 1000 can capture: NET_RAW is already in docker's default capability set, so nothing has to be added to the run config, and the capture stays non-promiscuous (`-p`) because going promiscuous would need NET_ADMIN, which is not. |
| `docker/entrypoint.sh` | Container PID 1 (under tini). Renders ETV-next's config from the station config, creates every channel's playout folder, optionally starts the two diagnostics, starts the daemon, waits for its first playout files, then starts `ersatztv`. Restarts a crashed daemon in place; exits when ETV-next dies. A diagnostic dying is ignored — the wait loop only ends the container for its two real children. |
| `.dockerignore` | Keeps `target/`, `.git/`, docs build output, and scratch out of the Docker build context. |
| `.env.example` | Template for the deploy-related env vars (`APP_IMAGE`, `UNRAID_HOST`, …). Real `.env` is gitignored. |
| `LICENSE` | Boilerplate. |
| `README.md` | Project intro: tagline, status (what exists vs. planned), clone-with-submodules, build/run commands, docs links. |

| `crates/etv-station/src/determinism.rs` | Determinism check (#168): generate a named channel twice from identical inputs — one read-only catalog handle reused for both passes, one pinned seed (an unset one is drawn once and reused, so an intentionally-unseeded channel — #46 — is not misread as a broken plugin), `GenerationState::empty()` for both passes, and one `ScoreInputs` snapshot (including `now`, read once) — and diff the resulting `entry_id` sequences. Reports identical, or the first position where the two disagree plus both entry ids. Diffs `resolve_channel_with_resume`'s output rather than any one hook's call, so it covers both plugin hooks — `pool_provider` and, since #169 landed, `sequencer` — with no per-hook code here. `window_start` is read once and shared by both passes for the same reason `now` is: a sequencer reads it as `ctx.window.from`, so reading the clock per pass would straddle an hour boundary now and then and report a correct daypart script as non-reproducible. Wired to `--check-determinism <channel>` in `main.rs`; not part of normal generation — never called from `daemon.rs`. |
| `crates/etv-station/src/lib.rs` | Library entry point. Re-exports the modules so integration tests and the binary share one surface. |
| `crates/etv-station/src/config/` | TOML config parsing (Phase C block/channel/entries schema): `station`, `channel`, `rule` (`[[rule.blocks]]` includes), `block` (`[program]`/`duplicates`/`[constraints]`/`[[entries]]`), `constraints` (`no_repeat_within`, `separate_by`/`separate_min_gap`), `entry` (kind-tagged item/query/collection/include), `pool` (#72 `pools` + `pattern`: `group_by`/`bucket_order`/`select`/`rotate`/`advance`/`on_short`/`chance`, a `take` that is a count or the word `all`, and a `from` that cuts the slice at `start`/`end`/`random` (#155), plus #115 per-pool `constraints` with `Pool::constraints` resolving a pool's own table against the block default, `BlockInclude::adjacency_reach` converting a pool-draw gap into channel positions, and the opaque `config` bag read through `etv_overlay::config_carrier::deserialize_config` so a non-finite float fails the channel at load naming the key — #130), `source`, `mode`, `order`, `filter`, `load`, `validate`. `load` resolves every environment reference — the `ETV_STATION_*` overrides and `${VAR}` in local item paths — through an `EnvLookup` function argument, with `process_env` the only reader of the real environment: `load` keeps its signature and hands the chain `process_env`, while `load_with_env`/`resolve_blocks`/`expand_env` take the lookup, so a test supplies a fixed table instead of exporting variables into the running process (#132). |
| `crates/etv-station/src/resolve.rs` | Resolve pipeline (#71): flattens `[[rule.blocks]]` into an ordered `ResolvedItem` list — resolve entries (inline items direct; `query` entries via `Catalog::resolve_query`, each `entry_id` → item; `collection` entries via name lookup + `Catalog::collection_members`, arriving already in stored `position` order so nothing re-sorts them — #107) → block `filter` (#197: `seasons`/`episode_ids`, each set narrows further — `seasons` needs the catalog, `episode_ids` doesn't; entries-block only, rejected on a pattern/sequencer block at validation) → `duplicates` (collapse before order) → `order` (`manual` keeps authored, else `Catalog::resolve_order`) → `mode`, then one channel-level adjacency pass (`constrain::order_no_repeat`) over the concatenated blocks. Takes `Option<&Catalog>`; with one it builds a canonical-path index so a manual `local` item inherits the catalog `entry_id` for its file (manual∩query collapse). Still rejects `include` entries and `fallback` (later issues). `resolve_channel_with_resume` adds the #72 resume map: a pattern block routes to `pattern::build` instead of the entries path and reports where each pool got to. It also carries the `fill` span — the airtime the caller still needs covered — which bounds one generation whichever shape the channel is: a pattern block with no authored `cycles` stops at the window rather than draining its pools (#140), and a channel with no pattern block is seated at its stored list position, cut at the item that covers `fill`, and reports the position it reached (#118). The cut runs before the adjacency pass, so that pass and the daemon's ledger both see exactly the items about to air; item lengths for it come from `estimated_runtimes` (in/out points → `catalog_duration` → one bulk `Catalog::durations_for` → the mean of what is measured → `scoring.nominal_item_secs`). `resolve_channel` passes `None` and is unbounded, starting every list at the top. A block naming `sequencer:` routes to `sequence::build` instead of either path (#169), and `resolve_channel_with_resume` carries a `window_start` — the instant the generation begins airing — so a daypart script asks what hour the generation starts rather than what hour the daemon is computing in. |
| `crates/etv-station/src/catalog/` | Unified sqlite-backed catalog (#47) — the durable store query-based channels resolve against, plus the ingesters that populate it (`ingest/`: local-FS + Plex). |
| `crates/etv-station/src/catalog/ingest/mod.rs` | Ingest module root; owns the shared `canonical_index` (canonical-path → `entry_id` over all provenance rows, non-`fs:` id wins) that both ingesters use for path-match inherit. |
| `crates/etv-station/src/catalog/mod.rs` | `Catalog` handle over a `rusqlite` connection (WAL, `foreign_keys=ON`). Upsert/read API for entries, provenance sources (incl. `all_sources` for ingest path-match), external ids, tags, and collections; two provenance rows on one `entry_id` = a deduped item. Two bulk lookups exist because the pattern engine asks them of every item of every pool on every generation: `show_ids_for` (series grouping) and `durations_for` (per-item runtime, so a generation knows when it has covered the window — #140). |
| `crates/etv-station/src/catalog/ingest/fs.rs` | Local-FS catalog ingester (#92). `ingest_roots` globs media roots + `ffprobe`s durations; `ingest_files` is the pure catalog-writing core with ingest-time path-match inherit (canonical path reuses an existing `entry_id` — Plex or prior scan — else `fs:<fnv1a>`) and `local_fs` provenance keyed by canonical path (idempotent re-scan). Writes no tags at all: the parent-directory `fs_dir` tag is gone (#123), because `add_tag` only ever inserted and an entry kept every folder its files had ever been in — `item.fs_dir` now derives the folder from `entry_sources.playback_path` at query time. A full pass also reconciles deletions (#144): every row it writes gets one identical `last_seen` stamp, rows left holding an older one (file moved, renamed, or deleted) are swept, and an entry whose last provenance row went with them is deleted too. Gated on `prune_absent` — the same contract as `ingest_collections` — which only `ingest_roots` sets, so a partial scan deletes nothing. |
| `crates/etv-station/src/catalog/ingest/plex.rs` | Plex catalog ingester (#91, core). `ingest_items` is the pure core: `entry_id` from the strongest Plex GUID (`imdb→tmdb→tvdb→plex`, `fs:` fallback) with path-match inherit onto a prior FS entry; Plex is authoritative so it always upserts metadata (incl. promoted `release_date` from `originallyAvailableAt` (#135), `edition`/`studio`/`absolute_episode` columns) + records every external id + a `plex` provenance row (ratingKey) + genre/cast/director/writer/producer/country tags (each namespace cleared and rewritten per entry, so a tag removed upstream doesn't survive a re-ingest). `ingest_labels` populates the `label` tag namespace separately (#136): Plex's bulk item listing never carries `Label`, so `PlexClient::fetch_labels` walks each section's label list and fetches each label's section-scoped members directly, and `ingest_labels` reconciles the whole namespace wholesale (`Catalog::clear_tag_namespace`) rather than per entry. `ingest_collections` populates `collections`/`collection_items` (members resolved ratingKey→`entry_id`, in Plex order). `ingest`/`PlexClient` (ureq) is the thin HTTP layer, taking the connection as a `PlexEnv` argument rather than reading the environment itself; `PlexEnv::from_env` is the module's single read of `PLEX_URL`/`PLEX_TOKEN`/`MEDIA_PATH_FROM`/`MEDIA_PATH_TO`, returning `None` for an unconfigured Plex and warning when exactly one of the pair is set (#132). Collections/playlists, delta sync, and the refresh TTL are deferred to the daemon wiring (#96). |
| `crates/etv-station/src/catalog/schema.rs` | DDL + up-only migrations (version table, appended-never-edited) for the six locked tables: `entries`, `entry_sources`, `entry_external_ids`, `tags`, `collections`, `collection_items`. Migrations also carry one-off data cleanups where a fact stopped being stored — v4 deletes the `fs_dir` tag rows older binaries wrote (#123), now that the folder is derived from `entry_sources` at query time. |
| `crates/etv-station/src/catalog/model.rs` | Typed model: `Entry` plus `Source` / `ExternalNs` / `TagNs` enums for the fixed-set discriminators (open-ended `type` stays a string). |
| `crates/etv-station/src/catalog/identity.rs` | Deterministic `entry_id` derivation: GUID priority `imdb → tmdb → tvdb → plex`, `fs:<fnv1a>` path fallback, and the pure string half of canonical-path (root-strip + separator-normalize). |
| `crates/etv-station/src/catalog/order.rs` | Order resolution engine (#69). `Catalog::resolve_order` applies a `config::Order` to a resolved `entry_id` set: `field:dir` compound sorts via SQL `ORDER BY` (nulls last per term, implicit `entry_id` tiebreaker), `manual` keeps authored order, `random` is a SplitMix64-seeded Fisher–Yates shuffle (deterministic per seed). Every case is a function of the ids alone — a collection's authored sequence is deliberately *not* an order (#107), since `collection_items.position` belongs to the (collection, item) pair and a flat id set can't say which collection to read; it is emitted already-ordered by a `kind = "collection"` entry via `Catalog::collection_members`. `score` went the same way (#108) — it needed a plugin the id list can't reach. Non-sortable fields are errors. |
| `crates/etv-station/src/catalog/query.rs` | CEL→SQL `WHERE` translation (#68). Walks the `cel` AST for a channel `query` expression over `item.*` and compiles it to a parameterised `WHERE` (scalar comparisons/`in`/`contains`/`startsWith`/`matches`, tag/collection/source membership via `EXISTS`, boolean `&&`/`\|\|`/`!`); `Catalog::resolve_query` runs it. `item.fs_dir` is membership too, but derived rather than stored (#123): an `EXISTS` over `entry_sources` comparing the folder computed from `playback_path`, so it names where an entry's files are now and an entry with files in two folders matches either. `register_functions` installs the sqlite functions a clause can call — `REGEXP` (regex crate) and `parent_dir` — on every connection, read-only handles included. Unknown fields and tag comparisons are config errors; empty result is `[]`, not an error. |
| `crates/etv-station/src/catalog/error.rs` | `CatalogError` — open / sqlite / bad-row variants. |
| `crates/etv-station/src/atomic.rs` | `atomic_write_json` — temp file in same dir, fsync, rename. Used by every JSON emission (playout, resume, durations cache). |
| `crates/etv-station/src/constrain.rs` | Post-order adjacency pass (#73). `order_constrained` enforces both spacing rules over one list — the channel's concatenated entries-block items, or (since #115) one pool's own resolved list — plus `conflicts_with_recent`, the same rule asked of a sequence already emitted one item at a time, which is what the pattern draw loop uses: `no_repeat_within` (same `entry_id`) and `separate_by`/`separate_min_gap` (items sharing any value of a multi-valued field), reaching back across the generation seam via the ledger's `tail`. Deterministic greedy (defer a violator, take the first eligible item behind it) plus a bounded swap-repair; unsatisfiable violations are accepted and *reported* via `Ordering::unresolved` so the caller can log them. The list is linear, not circular: `Sequential` plays it once, so its own head and tail never air adjacently. |
| `crates/etv-station/src/history.rs` | `history.db` (#70, #111) — the play-history store: one sqlite row per scheduled airing (`channel`, `entry_id`, `show_id`, scheduled `start`, `played_at`, `error_card`), in its own station-wide database file, deliberately **not** the catalog, because play history is not rebuildable and the catalog's delete-and-re-ingest property depends on everything in it being. The per-series resume cursor is a *projection* of it, so where each show left off lives in exactly one place. Times are stored as epoch nanoseconds rather than RFC3339 text, which sorts wrong when the fractional part is zero. "Last" is the greatest `start`, not the last row inserted, so appending out of schedule order cannot silently rewind a series; equal starts resolve to the later insertion. The resume cursor counts error-card airings and the adjacency tail excludes them. Replaced the per-channel `.history` JSONL, which is migrated once per channel on first start and then left in place. |
| `crates/etv-station/src/resume.rs` | `.resume` sidecar (#72) — the scheduling state a channel persists that the ledger cannot express: per pool, which series is next in the rotation, and for a channel with no pattern block, `position` — how far into its flat authored list the next generation starts (#118). Read at generation start, written at the window seam. Also defines `GenerationState` — that state plus the ledger's cursor projection — which is what one generation is handed. Also holds the checkpoints — pool rotation *and* list position entering each unaired generation — that let a restart rewind, drop its unaired chunks, and regenerate them from the current config. A missing, corrupt, or future-version file starts every pool and every list from the top rather than failing the channel. |
| `crates/etv-station/src/pattern.rs` | Pattern interleave engine (#72) — resolves each pool, groups it into series by catalog `show_id`, or by `show_id` + season under `group_by: season` (#155; an item with neither is its own series), then walks the `{pool, take}` template drawing per `select`/`rotate`/`on_short`. `take: "all"` empties the series the visit picked, sized after the pick rather than before it, which is what makes "a random season, start to finish" a config line rather than a rule in the walk; `derive_cycles` counts a take-all step in series rather than items. A step's `from` (`start`/`end`/`random`) seats the picked series' cursor before the first draw, so "the last three" and "three from a random point" stay consecutive and in play order — a thing no sort can express, since the sort that would choose the slice is the one that decides play order. A pool's `bucket_order` re-sequences the series without touching their contents, read off a second `resolve_order` pass over the same ids so there is one implementation of what a field sort means. A season series reads the ledger cursor under its show's key, so only the season holding the last-played episode advances. A series that runs off its end restarts — there is no drop/retire behaviour. **How long one pass runs (#140):** an authored `cycles` is taken as-is; with none, draining the largest pool once is only the ceiling and the walk stops at the first cycle boundary whose laid-down runtime covers the `fill` span the daemon passes (`target - from`), so a 51-pool channel covers a day rather than eleven years. Item runtimes come from one bulk `Catalog::durations_for` per pool, loaded only when a `fill` is given; an item the catalog never measured counts at its pool's mean, and a pool with no measured item at all cannot bind the window. Enforces each pool's effective `constraints` inside the pool (#115), so the adjacency repair can never reorder the interleave: once over the flat list before grouping, and again per draw via `PoolRuntime::eligible_from`, which skips a series whose next item clashes with what the pool just emitted — the half that actually catches the rotation's repeats, since a resolved set holds each id once. The seam is the aired tail narrowed to that pool's own items; a draw with no clash-free option airs anyway and is counted for the `constraints.unsatisfied` warning. Seeded keyed rolls (SplitMix64) make `select = "random"` and a step's `chance` reproducible for a pinned seed. |
| `crates/etv-station/src/sequence.rs` | Sequencer hook (#169) — the second plugin hook. A block naming `sequencer:` gets its timeline from a Rhai script instead of the `pattern.rs` walk. Resolves the block's pools through `pattern::resolve_pool_sources`/`resolve_pool_series` (factored out of `pattern.rs` so the two arrangement paths cannot drift on what a pool resolves to) and marshals `ctx.pools.<name>` via `score::load_items` — full item maps, not bare ids, because a daypart script has to prefer items that fit the time left before its next boundary and ids carry no durations (ADR 0004). Hands the script `ctx.window.from` (the instant the generation begins airing, threaded down from `daemon.rs` through `resolve_channel_with_resume`), each pool's own `config:` as `ctx.pool_config.<name>` (#14 — the existing generic pool carrier, not a new schema field), plus read-only resume inputs. Registers a `local_time(unix_secs)` global function on the engine — `#{weekday, hour, minute}` in the station's configured `tz` (`ScoreInputs::tz`, UTC at the stateless entry point) — so a script can re-read the clock at any cursor it computes, not only at `ctx.window.from`. Validates every returned id belongs to one of the block's pools, truncates an overrun at the window boundary, and derives new resume state from what came back. Mutually exclusive with `pattern` at load. Worked samples: `examples/plugins/foryou-sequencer.rhai`, `examples/plugins/daypart-sequencer.rhai` (#14). |
| `crates/etv-station/src/score.rs` | Scorer plugin host (#74, capability-gated per #167) — runs a pool's Rhai script and returns what it picked. The script declares which hooks it implements (`hooks()`, #159) and which host capabilities it needs (`capabilities()`, #167) at config load, read by compiling the script and calling that one function so `sources()`/`pick()` never run during the check. It declares its catalog queries in `sources()` (resolved once, up front, so a malformed expression fails before any ranking) and ranks them in `pick(ctx)`. `ctx` is a registered custom type rather than a plain map: `ctx.sets` (catalog queries) and `ctx.history` (pooled watch history) are fallible getters present only when the matching capability was declared *and* granted, so an ungranted reach fails naming the capability instead of quietly returning nothing. The target count, recently-aired tail, generation clock, and the pool's own `config` stay unconditional. `load_items` and `engine()` are `pub(crate)` so `sequence.rs` (#169) shares one item-map marshalling and one engine configuration rather than a second that could drift. The station computes no score itself and no score value crosses back — each `pick()` entry is either a bare `entry_id` string or a record widening it with an optional `metadata` blob (opaque, carried to `PlayoutItem::metadata` on both a `pattern:` and a `sequencer:` block alike, refusing a non-finite float via `etv_overlay::config_carrier` the same way `Pool::config` does) and/or a `take` override for that entry's series (#166; carried through pool resolution onto `pattern::PoolRuntime`, honoured for `take` by #173 — `metadata` reaches every block kind as of #201). Empty and duplicate picks are errors, not short channels. |
| `crates/etv-station/src/tautulli.rs` | Tautulli watch-history client (#74) — at most one `get_history` call per *audience* per station tick, shared by every channel that wants that audience (#126, #112), and none at all on a station whose channels name no scorer plugin, because a pool with a `plugin:` is the only thing that ever reads the result (#131). An audience is a `HistoryScope`: `AllUsers` (the unfiltered server-wide call, the default) or `User(String)` (one account, sent as `user_id` when the value parses as an integer and `user` otherwise, percent-encoded via `ureq`'s `.query()` so a name like `Sam + Alex` survives). Joined to catalog entries by Plex `ratingKey`. Configured only by `TAUTULLI_URL` / `TAUTULLI_API_KEY`, never by tracked config, and read in exactly one place: `credentials_from_env` returns the `(url, key)` pair (or `None`) and `fetch_rows(url, key, scope)` takes it as an argument, so a test withholds the connection instead of deleting env vars out of the running process (#132). Unreachable or unset yields an empty history rather than an error, so an outage degrades a scorer's ranking instead of stopping the channel. A fetch that produced no rows — unset, unreachable, or simply an idle server — skips the catalog join entirely, so the `tautulli.join` INFO only ever appears when there were rows to join (#141). |
| `examples/plugins/taste-engine.rhai` | The worked example scorer plugin (#74). Declares its catalog queries in `sources()`, splits them by the calling pool via `ctx.pool`, and ranks in `pick(ctx)`: recently-aired items suppressed for a replay TTL, a linear-decay boost from the pooled watch history, small nudges for newly-released and season-one items. When the replay window covers the whole library it falls back to the longest-ago airing rather than picking nothing. Every number in it is the script's opinion, not the station's. |
| `examples/plugins/daypart-sequencer.rhai` | The reusable dayparting sequencer (#14, ADR 0004) — every network-mirror channel points `sequencer:` here rather than carrying its own script. Reads each pool's `weekdays`/`hour_start`/`hour_end` from `ctx.pool_config.<name>` (exactly one pool with neither key is the default that fills unclaimed hours), fails `arrange()` naming both pools if two dayparts' hours and weekdays overlap, and places items by walking `ctx.window.from` forward: at each step it finds the active daypart via `local_time()`, computes the next local-hour boundary that changes it, and prefers whichever of that pool's items fits the remaining time — the item at the pointer plays anyway when nothing fits, so a daypart starts late rather than truncating or leaving a gap. Restarts every generation; a resuming daypart is future work. |
| `crates/etv-station/src/duration.rs` | `DurationCache` (`.durations.json` sidecar) keyed by `(path, mtime)`. Probes Local sources via `ffprobe`; Lavfi/Http durations come from config. Prunes entries whose path is no longer referenced by the channel's current items so the sidecar doesn't grow unboundedly. |
| `crates/etv-station/src/rule.rs` | `Rule` trait + the `Sequential` sequencer, plus `phase_at` (where a channel anchored in the past joins its list) — plays the resolver's `ResolvedItem` list **once** from a given start, walking cumulative item durations to fill the chunk window. The only emission model: each generation lays its list after the last one, so a channel whose list never changes loops by repetition rather than by a separate rule. |
| `crates/etv-station/src/scan.rs` | Discover existing `{start}_{finish}.json` files in a channel's `output_folder` for startup catch-up. |
| `crates/etv-station/src/emit.rs` | Chunk slicer + filename formatter. Walks `tz::add_chunk` boundaries and writes one playout file per chunk via `atomic_write_json`. `chunk_filename` is shared with `channel_card.rs`, which rewrites a chunk under its new name after pulling cards back out of it. |
| `crates/etv-station/src/channel_card.rs` | The channel-level error card (#117) — what a channel puts on screen when its own loop has died, as opposed to `error_card.rs`'s per-item card for one unreadable file. `cover_after_written` fills the span between the end of everything already written and `now + window_days` with five-minute lavfi cards, emitted through `emit::emit_window` so they land in the same chunk files as real programmes; calling it again extends the run rather than duplicating it. `wipe_cards_from` takes them back out again for the recovery path — item by item, not file by file, because the run starts mid-chunk and the first file of it holds real, still-airing content alongside the cards. |
| `crates/etv-station/src/error_card.rs` | The on-screen card that takes a slot when its file cannot be played (per item) and the one that covers a channel whose loop has died (`make_channel_card`, #117). Both are authored `lavfi` sources — black, with the title or channel name that was meant to air and the reason it is not — so the emitter, the playout schema, and ETV-next handle them as ordinary items. `drawtext_safe` reduces arbitrary error text to something an ffmpeg filter-graph argument can carry literally, rather than trying to escape it. Font from `ETV_STATION_ERROR_FONT`, defaulting to the Noto the runtime image ships. |
